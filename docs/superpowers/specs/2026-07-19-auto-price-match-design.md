# 新模型自动匹配价格 · 设计文档

日期：2026-07-19
状态：已获用户批准

## 背景与问题

TokenLens 已有两种定价方式，但都需要用户主动操作，且入口隐蔽：

1. 手动改价：「模型」页卡片 ✎ 按钮 → `POST /api/prices` → 写入 `data/prices.json`
2. 手动导入：「模型」页「⇓ 从 models.dev 导入官方价格」按钮 → `POST /api/prices/import`

实际问题：

- 新模型（尤其是自动采集每 10 分钟扫描日志发现的模型）出现后，费用记为 $0，用户难以察觉
- 模型卡片没有"未定价"标识，未定价模型只是费用显示 $0
- 后端 `GET /api/prices` 已返回 `unpriced` 列表，但前端从未使用

## 目标

新模型首次出现在记录里时，后台自动从 models.dev 匹配价格并保存；匹配不上时让用户能一眼看到并手动补价。

**更新策略（用户已定）：只补缺失。** 自动匹配只写入 `prices.json` 中不存在的键，绝不覆盖已有价格（包括手动修改的和之前自动导入的）。官方调价需用户手动点「导入」按钮刷新。

## 方案：服务端懒触发 + 目录磁盘缓存

对比过的备选：前端驱动（打开模型页才触发，不覆盖自动采集路径）与仅手动录入时触发（同样不覆盖自动采集）。服务端懒触发是唯一同时覆盖"自动采集发现新模型"与"手动录入新模型"两条路径的方案。

## 详细设计

### 1. models.dev 目录缓存

新文件 `data/models_dev_cache.json`：

```json
{
  "fetched_at": 1721350000,
  "index": { "kimi-k3": {"input": 3.0, "output": 15.0, "cache_read": 0.3}, ... },
  "unmatched": { "some-model": 1721350000 }
}
```

- `index`：把现有 `import_models_dev()` 里的目录索引构建逻辑（provider 优先级排序、跳过 0 价订阅条目、cache_read 解析）抽成可复用函数，索引结果（小写模型 id → 价格 entry）落盘
- TTL 24 小时：缓存未过期时自动匹配直接用本地 `index`，不访问网络
- 手动点「导入」按钮：强制重新拉取目录并刷新缓存（保持现有"强制刷新 + 覆盖匹配到的价格"行为）
- `unmatched`：记录匹配失败过的模型及时间。目录未刷新前，自动匹配不再重复尝试这些模型；目录刷新后清空重试（models.dev 会持续收录新模型）

### 2. 自动匹配触发

在 `merged_records()`（server.py:110）返回前：

1. 找出记录中出现、但 `prices`（默认价格表 + prices.json 合并结果）里没有的模型
2. 排除 `unmatched` 名单中的模型
3. 若有剩余 → 起一个 daemon 后台线程执行匹配（全局锁防止并发重复执行），不阻塞 HTTP 响应

匹配流程：读缓存（过期则先拉取刷新）→ 对每个无价格模型走现有匹配逻辑（`MODEL_ALIASES` 别名 → 精确 → 子串）→ 命中的经 `save_user_price()` 写入 prices.json → 未命中的记入 `unmatched`。

因为 `merged_records()` 同时服务 `/api/records`（含自动同步轮询）与 `/api/prices`，自动采集和手动录入两条路径都被覆盖，无需单独挂钩 `collect_loop` 或 `POST /api/records`。

### 3. 前端"未定价"可见性

- `GET /api/records` 响应中新增 `unpriced` 字段（后端本来就能算，与 `/api/prices` 逻辑相同），前端不再额外请求 `/api/prices`
- 模型卡片：无价格模型的 ✎ 按钮旁显示橙色"未定价"小徽标
- 「模型」页提示条：存在未定价模型时，文案追加"N 个模型未定价，点卡片 ✎ 设置"
- 保留录入弹窗现有的"该模型暂无价格信息"提示（app.js:537）

### 4. 边界与错误处理

- 默认价格表（pricing.py `MODEL_PRICES`，Kimi 系列等内置价）里的模型视为已有价格，不触发匹配
- 网络失败 / 离线：静默跳过，不弹错；下次检测到未定价模型时再试（有 `unmatched` 防重复，网络失败本身不记 unmatched）
- 并发：HTTP 请求线程与后台匹配线程可能同时写 `prices.json`——匹配线程与手动 `POST /api/prices` 都用现有 `_lock` 保护写文件
- 0 价订阅条目：沿用现有逻辑跳过（import_models_dev 里 `input<=0 and output<=0` 跳过）

### 5. 非目标（YAGNI）

- 不做设置开关（离线时本来就会静默失败）
- 不追踪价格来源标记（"只补缺失"策略下不需要区分手动/自动）
- 不改动手动导入按钮的覆盖行为
- 不接 models.dev 以外的数据源

## 测试

- 单元级：目录索引构建（含 0 价跳过、provider 优先级）、缓存 TTL 判断、unmatched 防重复、"只补缺失"不覆盖已有价格
- 集成：手工构造记录含新模型 → 触发自动匹配 → prices.json 出现新键；断网场景静默跳过
- 前端：未定价模型卡片显示徽标与提示条计数

## 交付备注

改动文件：`server.py`（缓存 + 触发 + `unpriced` 字段）、`static/app.js`（徽标 + 提示条）、`static/style.css`（徽标样式）。`pricing.py` 与 `collector.py` 不动。完成后需重新打包 TokenLens.exe（沿用项目现有打包流程）。
